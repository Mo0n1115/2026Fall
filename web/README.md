# 틈 기능 시제품

저장소 루트에서 `python3 -m http.server 8080 --bind 127.0.0.1 --directory web`로 실행한다. 로컬 브라우저에서 해당 서버에 접속한다. API 키와 패키지 설치는 필요 없다. 클라우드에서 실행한 서버가 사용자 PC에 자동 공개되는 것은 아니다.

`node --test tests/routes.test.mjs`로 추천 로직을 검증한다.

## 응답 구조

`routes.mjs`의 `fixture`는 조사 기록을 참고한 합성 예시다. 실제 TMAP 응답을 캡처한 파일이나 전체 명세가 아니다.

- `metaData.plan.itineraries[]`: 경로 후보
- `totalTime`: 초 단위 총 시간
- `transferCount`: 환승 횟수
- `totalWalkDistance`: 미터 단위 도보 거리
- `legs[]`: 이동 구간. `mode`, `route`, `sectionTime`, `start`, `end`의 일부 필드만 사용

혼잡도 점수는 이 예시 응답에 포함하지 않고 별도로 결합한다. 같은 척도로 작성한 가상 값으로만 추천 순서를 검증한다. 실제 연동 시 데이터 출처·유형·기준 시각·지원 범위와 오류 상태를 추가해야 한다. `normalize`가 응답 구조를 내부 모델로 변환하고 `recommend`가 추가 시간 제한과 혼잡도·환승·도보 순 비교를 담당한다.

입력한 장소명은 표시용이며 실제 검색이나 길찾기를 하지 않는다. 예시 노선과 구간은 실제 이동에 사용하면 안 된다. 지도와 실제 승강장·출입구 정보, 자동 하차 알림·재탐색은 미구현이다.

위치 확인은 HTTPS 또는 브라우저가 보안 컨텍스트로 인정하는 로컬 환경과 권한이 필요하다. 좌표를 저장하거나 서버로 전송하지 않는다. 중단·안내 종료·도착·화면 숨김 시 감시를 해제한다. 모바일 잠금·백그라운드 지속 추적을 제공하지 않는다. 실제 기기의 GPS 검증은 별도로 필요하다.

## 지도 중심 버전

Leaflet 1.9.4와 OpenStreetMap 표준 타일을 사용한다. Leaflet은 npm 배포본의 SHA-512 무결성을 확인한 뒤 `vendor/`에 포함했으며 라이선스를 함께 배포한다. 지도 표시는 인터넷과 `tile.openstreetmap.org` 접속이 필요하다. 이 클라우드에서는 타일 요청이 프록시 403으로 차단되어 실제 타일 표시를 검증하지 못했다. 타일 요청에는 화면 영역이 지도 제공자에게 전달되며, 위치 좌표 자체를 앱 서버로 전송하거나 저장하지 않는다.

위치 권한 허용 후 GPS 마커와 정확도 원을 갱신한다. 지도를 끌면 따라가기가 해제되고 내 위치 버튼으로 복귀한다. 화면 숨김·추적 중단·안내 종료·도착 시 추적을 종료한다. 위치 갱신은 브라우저와 장치가 제공하는 빈도에 따르며 실제 기기 검증이 필요하다. 지도는 현재 실제 기능, 경로와 혼잡도는 예시다. 경로선·위치 매칭·자동 이탈 감지는 미구현이다.

## 태블릿에서 접속하기

GitHub Pages 배포 설정을 준비했다. 최초 활성화와 실행 확인 방법은 [배포 안내](../docs/github-pages.md)를 참고한다. 푸시·Pages 활성화·배포 성공 전에는 공개 사이트가 준비된 상태가 아니다.

## 지도 위 예시 경로 비교

카드 선택과 지도 경로선 선택을 연결했다. 선택한 경로는 녹색(편하게) 또는 주황색(빠르게), 다른 후보는 회색, 도보 구간은 점선으로 표현한다. 출발·도착·환승 지점을 표시하고 화면 패널을 피해 전체 경로가 들어오도록 지도를 맞춘다. 경로 전체 보기를 선택하면 GPS 따라가기를 해제하며, 내 위치 버튼으로 복귀할 수 있다.

`passShape.linestring`의 경도·위도 문자열을 내부 위도·경도 좌표로 변환한다. 현재 좌표는 직접 만든 합성 개략선으로, 실제 도로·선로·승하차 위치나 입력 장소의 검색 결과가 아니다. 빈 좌표나 잘못된 좌표는 그리지 않으며 직선 경로를 자동 생성하지 않는다. 실연동 시 API의 검증된 선형을 사용해야 한다. 예시 JSON 구조와 실제 응답은 여전히 구분된다.

## 성향 및 칸별 착석 예시

빠르게/편하게 라디오 선택과 지도·카드·상세 안내를 동기화한다. 지하철 구간에서는 `seating.mjs`의 합성 데이터로 일반 빈좌석 수 → 입석 인원 순의 칸 추천을 보여준다. 노약자석·임산부석은 일반 빈좌석 계산에서 제외하며, 표시하는 칸-문 위치 역시 가상이다. 승강장 번호가 아니다. 실제 착석 확률·칸별 혼잡도·좌석 점유·차량별 편성과 문 위치는 미연동 상태다.

전체 로직 검증 명령: `node --test tests/*.test.mjs` (저장소 루트). 실제 기기나 인증 API의 검증을 대신하지 않는다.

## 도착 타이머 예시

`arrivals.mjs`에서 절대 도착 시각을 만들어 구간별 첫 번째·다음 차량의 초 단위 카운트다운을 표시한다. 도보는 제외하고, 환승 이후 구간은 이전 구간 시간을 고려한 가상 시각을 사용한다. 현재 시각 기준 카운트다운이며 실제 ETA·환승 성공 판단은 아니다. 검색·성향 전환만으로 기준 시각을 초기화하지 않는다. 예시 재생성 버튼을 누르면 선택 경로의 가상 정보를 새로 만든다.

예시 유효 기간은 생성 후 2분이며 실제 공급자의 갱신 주기가 아니다. 만료된 정보는 갱신 필요로 표시한다. 예정 시각을 지나도 도착으로 단정하지 않고, 누락·시각 오류를 구분한다. 알림과 자동 안내 전환, 실제 도착 API 재조회는 미구현이다.

## 지도 위 시간 배지와 하단 패널

경로의 소요 시간 배지를 눌러 성향·카드·지도 경로를 함께 전환한다. 1024px 이하 화면에서는 반투명 하단 패널을, 넓은 PC 화면에서는 좌측 패널을 사용한다. 접기/열기는 버튼으로 동작하며 드래그 조절은 아직 지원하지 않는다. 경로 전체 보기와 패널 크기 변경 시 가려진 영역을 고려해 경로를 맞춘다.

## 압축 경로 비교와 현재 구간 카드

비교 카드에 구간별 시간 막대와 첫 차량 도착 타이머·혼잡도·좌석 요약을 표시한다. 버스 잔여석·남은 정거장은 미연동으로 표시한다. 전체 도착/칸별 좌석/이동 단계는 상세 펼치기로 제공한다. 안내를 시작하면 현재 구간 정보만 있는 하단 카드로 전환하며, 수동 이전/다음 단계에 맞춰 지도와 표시 정보를 갱신한다. 도보 단계에는 이전 차량의 타이머가 남지 않는다. 안내 종료 시 비교 화면으로 복귀한다.
