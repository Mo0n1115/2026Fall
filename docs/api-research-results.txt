1) 요약

조건부 우선안: TMAP 대중교통 API(상세 경로·도보) + 지역별 버스 도착/혼잡도(서울·경기·인천) + 서울교통공사 과거 혼잡도 통계. 상세 지하철 안내가 중요하면 ODsay를 비교 평가하되 상업적 이용·재정렬·타사 데이터 결합·보관 권한부터 서면 확인한다. 최종 공급자 선정·비용 지출은 제안으로 남긴다.

[공식 문서 확인] TMAP은 대중교통 구간과 도보 상세 경로를 제공한다[S1,S2]. ODsay에는 출입구·방향·빠른 환승 관련 필드와 별도 도보/멀티모달 API가 있다[S4]. 서울·경기·인천 버스의 혼잡도는 서로 다른 코드와 제공 범위를 사용한다[S9~S12].
[공식 문서 확인] 중요한 변경: ODsay Basic은 2026-08-20부터 30건/일, 기간 제한 없음[S6,S7]. 과거 1,000건/일 자료를 현재 한도로 사용하면 안 된다.
[공식 문서 확인] SK '실시간 열차/칸 혼잡도'와 '진입 역 기준 실시간 열차/칸 혼잡도' 상세 문서에는 2025년 11월 서비스 종료가 명시돼 있다[S15,S16]. 메뉴·소개·옛 뉴스가 남아 있어도 신규 서비스의 실시간 공급원으로 선정하지 않는다. 실제 종료 응답은 미실행.
[공식 문서 확인] TMAP에 함께 안내된 혼잡도 /stat/ API는 통계성이다. 10분은 시간 구간 크기이며 실시간 갱신 주기로 해석하지 않는다[S13,S14].
[미확인] 수도권 전역의 실시간 칸별 혼잡도, 모든 운영기관의 승강장 번호, 표지판·층·계단·엘리베이터를 연결하는 실내 보행 그래프, 실시간 대기를 포함하는 전역 최단 경로 보장은 확보하지 못했다.
[제안] 첫 버전의 '가장 빠르게'는 '조회된 후보 중 예상 총시간이 가장 짧은 경로'로 설명한다. '편하게'는 사용자 추가시간(기본 15분) 이내 후보를 혼잡도→환승→도보 순으로 재정렬하되 자료 종류·범위·누락률을 함께 표시한다. 좌석 확보를 보장하지 않는다.

- [공식 문서 확인] ODsay 운영정책 8항은 기본 용도 외 분석·대용량 사용에 사전 동의를 요구한다. 이용약관 4.5.10은 무단 복제·저장·가공·배포·제3자 전송을 제한한다. 6.2(API 이용 대가), 6.6(비상업·광고 제한 및 유료 앱 예외)이 함께 있어 '틈' 수익모델·후보 재정렬·캐시 허용은 서면 확인이 필요하다. 운영정책 10항에 상표 표시 의무가 있다[S7].
- [공식 문서 확인] TMAP /terms: 얻은 데이터는 저장 후 24시간 이상 사용할 수 없다[S3]. 24시간을 영구 DB 구축·재배포 허가로 해석하지 않는다. 혼잡도 별도 상품에 이 조건을 자동 적용하지 않는다.
- [미확인] TMAP/SK의 광고·유료 웹앱, 타사 지도 및 타사 혼잡도 결합, 결과 재정렬, 출처 문구·로고, 재배포·파생 데이터 보관의 구체 권리. SK 회원약관 페이지는 동적 본문 확인을 완료하지 못했다.
- [공식 문서 확인] 서울 버스와 서울 지하철 도착은 공공누리 1유형(출처표시; 상업 이용·변경 가능), 경기 상품은 이용허락범위 제한 없음[S9,S11,S18]. 인천 상세 페이지는 1유형이나 catalog JSON에는 제3자 권리 문구도 있어 적용범위 재확인이 필요하다[S12]. 캐시 권리를 다른 공급자에 전이하지 않는다.
- [미확인] 공공 데이터별 재배포 시 원본·수정일·제3자 표시 세부 조건과 API 이용약관상 보관 제한. 계약 확인 전 실제 응답 원문을 장기 저장하지 않는 설계를 제안한다.

3-A) 인증·호출 명세 요약(전부 문서 확인, 실호출 아님)

TMAP 상세 경로[S2]
POST https://apis.openapi.sk.com/transit/routes
헤더 appKey(상품 이용 등록 필요), JSON body startX/startY/endX/endY 필수. WGS84 경도/위도 순서. count=1~10(기본10), lang, format. searchDttm=yyyyMMddHHmm은 지정 시각의 운행 여부(service)를 안내하는 타임머신 기능으로 설명됨. 도착 희망 시각 역산이나 실시간 운행 예측 보장은 미확인. 시각 문자열의 명시적 timezone·자정 이후 영업일 처리 문의 필요.
응답 metaData.plan.itineraries[]: totalTime(초), transferCount, totalWalkDistance(m), legs[].sectionTime(초), distance(m), mode, route/routeId, service, passStopList, passShape.linestring, steps[].description/linestring. 후보 최대10이 전체 가능한 경로를 뜻하지 않음. 최단 보장·정렬식·대기 포함 정의는 미확인.

ODsay[S4,S5]
GET/POST https://api.odsay.com/v1/api/searchPubTransPathT
apiKey, SX/SY/EX/EY. SearchPathType=0전체/1지하철/2버스, OPT=0추천/1타입별.
pathType=1지하철/2버스/3혼합, info.totalTime/totalWalk, subPath, mapObj→loadLane 그래픽 데이터. 평균배차 필드는 실시간 대기와 구별. busTransitCount/subwayTransitCount는 이름만 보고 '승차 수-1'과 동일시하지 말고 실제 응답으로 의미 확인.
별도 maasRP: WGS84, SearchTime(출발 yyyyMMddHHmm), SearchMethod 필수; totalTime은 rps.duration 합(분). 별도 searchWalkPathV2: opt(reco/short/wide), loc(경도,위도 좌표셋); 직선거리 30km 제한. 각 상품 권한·별도 요금·지역 지원 확인 필요. 일반 길찾기와 멀티모달 명세를 섞지 않는다.
문서 오류 예: -8형식, -9누락, 6서비스지역외, -98출도착700m이내, -99결과없음. HTTP 상태와 API 오류 코드 별도 기록. 초당 제한 실제 응답 미확인.

브라우저/CORS 및 서버 중계
[공식 문서 확인] ODsay 가이드에 JavaScript 예시와 URI/서버 플랫폼이 있고, 공공 API 일부는 CORS 때문에 서버 호출이 필요하다고 안내한다[S5]. 이것이 모든 endpoint·임의 Origin의 CORS 성공 증거는 아니다.
[미확인] 이번 조사에서 인증키 없이 CORS preflight·Access-Control-Allow-Origin·실제 도메인/IP 제한은 검사하지 않았다.
[제안] HTML/CSS/JS→자체 HTTPS 서버→공급자. 비밀키는 서버 secret에만 두며 URL·헤더 로그에서 제거. 공급자별 일/월 예산·요청 병합·재시도 상한을 둔다. HTTP 429 외 HTTP200 업무오류도 처리하며 실패를 데이터 없음으로 바꾸지 않는다.

ID 연결 설계(제안; 실제 조인 미검증)
ODsay v1.8의 busLocalBlID/busProviderCode/busCityCode와 지역 공식 노선 ID를 우선 대조한다. 공급자·지역 namespace를 보존한다. 정류소는 이름 단독 매칭을 피하고 공개번호·좌표·정류소 순번·방향·노선 경유순서를 함께 확인한다. TMAP routeId/stationID는 지역 공식 ID라는 보장이 확인되지 않았으므로 교차표가 필요하다.
지하철은 공식 역코드표와 호선별 역 entity를 분리하고 환승역 복합체로 묶는다. SK의 211-R,211-0 같은 문자열을 정수 변환하지 않는다. 이름의 '역' 접미사·부역명·순환선을 명시적으로 정규화하고 방향은 이전/다음역으로 검증한다. 인천1·2호선, 수인분당선, 경강선 등은 SK 소개의 1~9호선과 같지 않다.
누락·지연·종료 처리(제안)
데이터 없음/지원범위외/공급자 오류/운행종료/오래됨을 별도 상태로 유지한다. 서울 0, 경기 -1, 인천255, SK 비운행시간 0을 '한산함'으로 변환하지 않는다. SK 통계 0은 운행하지 않는 시작·종착 조합일 수 있다[S13,S14]. 미래 환승 버스에 현재 첫째 차량의 혼잡을 그대로 대입하지 않는다. 재조회 가능 시 승차 직전에 갱신한다. 최대 허용 나이는 공급자 관측시각·SLA 확인 후 정하며 이번 조사에서 임의 갱신초를 확정하지 않는다.

5. TMAP 자료는 24시간 사용 제한을 적용하고 영구 보관 필요시 사전 확인. ODsay 응답 저장·가공은 명시 동의 전 미수행. 공개 문서 근거 파일과 API 데이터 보관을 구별.

7) 첫 버전 권고 및 웹 위치 기능

추천 조합과 대안(제안)
A. TMAP 상세 경로 + 서울/경기/인천 공공 버스 + 서울교통공사 통계: 지상 도보 단계와 혼합 경로를 먼저 검증하기 좋다. TMAP의 공개 ID 연결과 실내 안내 공백이 주요 위험.
B. ODsay 경로/역/환승 + 공공 실시간 + 허용된 도보 공급자: 빠른 환승·출입구 필드가 장점. Basic30건/일과 이용약관상 재가공·수익모델 제약을 해결하기 전 운영 선택 금지.
C. SK 통계성 칸 혼잡도: 계약상 지도결합·보관조건과 type별 역 목록 확인 후 선택 보강. 종료된 실시간 API는 제외.
공통: 전국 확대는 공급자 마케팅 범위와 별개로 운영기관·지역·수단별 실제 지원표를 만들고 미지원은 명시한다. 인천시청→수원은 경로 가능성과 혼잡 제공 가능성을 따로 검증한다.

추천 로직(제안)
- 동일 출발시각·동일 도보 기준으로 후보 집합 P를 정규화한다. Tfast=min(T(p)); 편한 후보는 T(p)≤Tfast+사용자허용분×60. 기본900초.
- 시간에는 접근/하차 도보, 이동, 환승 도보, 탑승 대기가 모두 필요하다. 공급자 총시간의 대기 포함 여부 확인 전 무조건 ETA를 더하면 이중계산 위험. 첫 버전에서 검증되지 않은 '실시간 총시간'을 표시하지 않는다.
- 혼잡 비교는 정의가 다른 원시 코드의 단순 평균을 피한다. 자료유형별로 분리하고 구간별 탑승 예상시각에 맞춘다. 유효 자료가 충분한 후보끼리 혼잡 노출(예: 탑승시간 가중치), 환승 수, 도보거리의 사전식 정렬을 제안한다. 지표의 가중치·단계 환산은 제품 정책이며 공급자 정의가 아니다.
- 정보 없음은0점/최저혼잡으로 두지 않는다. 자료가 다른 후보는 불확실성을 명시하고 환승·도보 비교를 제공한다. 모든 후보가 불완전하면 '혼잡 비교 불가'.
- 최단 후보 대비 추가시간 기준은 반환 후보 집합 안에서만 성립한다. 전체 교통망 전역 최적·대안 경로 완전성·좌석확보는 보장하지 않는다. 후보 밖의 편한 경로를 못 찾을 수 있다.
- 실시간 지연·막차·우회는 재탐색 사유. 경로가 없으면 오류/운행없음/미지원 구별 후 시간 변경·장소 수정 제공. 직선 연결을 실제 보행선으로 표시하지 않는다.

웹 위치(공식 문서 확인, 실기기 테스트 미실행)[S21~S27]
- watchPosition은 HTTPS secure context, 사용자 명시 권한 및 Permissions-Policy 허용 필요. 위치 변경에 success 콜백, 오류 콜백을 등록하고 watch ID 반환. clearWatch(id)로 감시 해제.
- coords.accuracy는 위·경도 오차를 m 단위로 표현하며 95% 신뢰수준. timestamp는 위치 취득시점의 Unix epoch 기반 밀리초. 화면 수신시각과 구별하여 오래된 값 판별.
- enableHighAccuracy는 정확도 요청이지 GPS 강제나 칸 판별 보장 아님. maximumAge는 허용 캐시 나이(ms), timeout은 취득 제한(ms); 권한/가시성 대기시간과 구별한다. 위치 거부·취득불가·timeout을 분리한다.
- W3C 2026-03-26 Candidate Recommendation 6.5는 fully active·visible 문서에 위치 업데이트 전달을 한정한다. 모바일 잠금·백그라운드에서 계속 갱신된다고 약속할 수 없다. 문서 규칙과 OS/브라우저별 실제 동작은 별도이며 이번 실기기 결과 없음.
- 알림은 위치 권한과 별도. MDN은 사용자 동작에서 권한 요청 및 모바일에서 service worker의 showNotification 사용을 안내한다. Apple 문서는 iOS16.4+ 홈화면 웹앱 Web Push 지원을 설명한다. Web Push가 지하 GPS 추적·정확한 하차 알림을 보장하지 않는다.
- 전경 복귀시 마지막 위치 나이 확인→새 위치 재취득→현재 단계 재확인. GPS만으로 지하철 현재 역·열차·칸을 확정하지 않는다. 사용자가 '탑승했어요/이 역이에요/이전·다음 단계'로 수정하고 자동 추정이 이를 즉시 덮어쓰지 않도록 한다.
- 미실행 기기 검증: Android Chrome/iOS Safari 및 홈화면 웹앱에서 권한 거절·회수, 잠금1/5/15분, 지하구간, 배터리절약, 통신끊김, 복귀, 수동단계 보정, 알림 지연. 시뮬레이션 결과를 실기기 결과로 쓰지 않는다.
