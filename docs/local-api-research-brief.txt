틈 웹앱 — 로컬 에이전트용 수도권 교통 API 조사 지시서

1. 목적과 서비스 요구사항
서울·수도권 대중교통 웹앱 ‘틈’에 사용할 API 조합을 공식 문서와 실제 응답으로 조사해주세요.
- 지하철·버스·도보와 혼합 경로를 제공하며 이후 지역 확대를 고려합니다.
- 가장 빠르게 이동: 도보·대기·환승을 포함한 총 소요 시간 최소화.
- 편하게 이동: 최단 경로 대비 추가 15분 이내에서 혼잡도 낮음 → 환승 적음 → 도보 적음 순으로 추천. 추가 시간은 사용자가 조절.
- 노선 번호·호선·행선지·운행 방향·승하차역/정류장·출입구·승강장·빠른 환승 위치(예: 3-2)·도보/환승 동선을 자세히 안내.
- GPS 현재 위치와 단계별 안내. 위치 불확실 시 사용자가 단계를 수정.
- 혼잡도는 실시간·예측·통계·정보 없음을 구분하며 좌석 확보를 보장하지 않습니다.
- HTML·CSS·JavaScript 기반 화면. 비밀 API 키는 서버에서 보호합니다.
조사만 수행하고 유료 가입·결제·실서비스 변경·GitHub 푸시는 하지 마세요.

2. 공식 자료 진입점과 접속 확인
클라우드에서는 다음 사이트에 대한 프록시 CONNECT가 403으로 거부되어 문서를 읽지 못했습니다. 서비스 자체의 접근 거부나 기능 검증 결과가 아닙니다.
로컬 접속 성공·실패와 확인 시각을 기록해주세요.
- ODsay: https://lab.odsay.com/guide/releaseReference
- TMAP 대중교통: https://transit.tmapmobility.com/
- 서울 버스 API: https://api.bus.go.kr/contents/sub02/getArrInfo.html
- 서울 열린데이터광장: https://data.seoul.go.kr/
- SK Open API: https://openapi.sk.com/
위 목록은 후보이며 기능 지원을 확정한 목록이 아닙니다.
주소가 바뀌면 공식 사이트에서 최신 문서를 찾아 최종 URL을 기록하세요.
경기·인천 공식 교통 데이터, 공공데이터포털, 운영기관 공식 자료도 필요하면 조사하세요.
블로그·검색 요약은 탐색 보조로만 활용하고 결론에는 공식 근거를 남기세요. 접근 통제를 우회하지 마세요.

3. 공급자·상품별 수집 항목
A. 기본 정보와 이용 조건
제공기관, 정확한 상품명, 문서 URL·확인일, 신규 신청 가능 여부, 종료·변경 공지.
지역·운영기관·노선·교통수단 지원 범위. 서울 지원을 수도권 전체 지원으로 해석하지 않기.
무료 한도, 유료 요금·과금 단위, 일/월/초당 제한, 승인 절차.
상업적 이용, 타사 지도·데이터 결합, 출처 표시, 캐시·재배포·보관 조건.
불명확한 가격·권리는 추정하지 말고 미확인으로 표시.
B. 인증과 호출
키 발급 절차, 필요한 상품 권한, 등록 도메인/IP 제한.
메서드, API 호스트·경로, 인증 위치, 필수 파라미터, 좌표계, 시간대·단위.
브라우저 직접 호출/CORS, 서버 중계 필요성, 오류·호출 제한 응답.
문서 예시와 실제 호출 결과를 구분.
C. 경로 탐색
복합·버스 중심·지하철 중심·대안 경로, 출발/도착 시각 지정, 실시간 대기·운행 반영.
후보 수·정렬 기준, 최단 경로 보장 여부, 총 시간에 포함되는 도보·대기·환승의 의미.
구간 시간·거리, 환승 횟수, 도보 거리, 지도 표시용 경로 좌표.
역·정류장·노선 ID, 공개 정류장 번호, 방향·행선지·급행, 역 입구·정류장까지의 도보 연결.
D. 혼잡도
버스와 지하철을 각각 조사하고 지역·노선·운영기관·시간대 범위를 명시.
차량/열차/칸/노선/역 중 제공 단위, 실시간/예측/과거 통계 구분.
단계·수치 정의와 코드, 관측 시각, 갱신 주기·지연, 미래 탑승 시각·방향 구분.
누락·오래된 값·운행 종료·빈 응답의 의미, 경로 API ID와 매핑 방법.
과거 통계를 실시간 값으로 취급하지 않기.
E. 상세 안내
출입구 번호·좌표, 승강장 번호·방향, 빠른 환승 승차 위치, 환승 통로·표지판·계단·엘리베이터·층·실내 동선.
출입구 번호와 승차 위치를 구분하고, 단순 환승역 이름과 실내 길안내를 구분.
제공되지 않거나 별도 데이터가 필요한 항목을 명시.

4. 실제 호출 — 권한과 키가 있을 때만
기존 키가 안전하게 제공되어 있고 사용 권한·무료 범위가 명확한 경우 최소한의 읽기 호출만 수행하세요.
키가 없으면 문서 조사를 완료하고 상품 신청·발급 절차를 기록하세요.
키를 채팅·파일·저장소·스크린샷에 포함하지 말고, 요청 쿼리·헤더·응답 로그에서 비밀과 개인정보를 제거하세요.
개인 위치 대신 아래 공개 장소를 사용하고 정확한 좌표·식별자를 조회해 기록하세요.
- 서울역 → 잠실역: 지하철 중심.
- 신촌역 주변 → 홍대입구역 주변: 버스 중심 후보.
- 서울역 → 판교역 주변 목적지: 혼합 경로 후보.
- 인천시청역 → 수원역: 경기·인천 지원 범위.
해당 입력에 버스·혼합 후보가 없으면 사실을 기록하고 다른 대표 입력을 선정하세요. 경로를 만들어내지 마세요.
실행 시각·시간대, 공개 장소, 비밀 제거 요청 조건, HTTP/API 코드, 후보 수·시간·구간·방향, 혼잡도 기준 시각·ID 매핑, 실제 상세 안내 필드를 기록하세요.
성공/실패/데이터 없음/미실행/지원 불가를 구분하고 불필요한 반복 호출을 하지 마세요.
필요한 응답 조각만 반환하고 보관 조건을 확인하세요.

5. 웹 위치 기능
MDN 등 공식 문서에서 HTTPS·위치 권한·watchPosition·accuracy·timestamp·clearWatch 동작을 확인하세요.
모바일 화면 잠금·백그라운드 위치 갱신·알림 제약을 조사하고, 문서 내용과 실기기 테스트 결과를 구분하세요.
GPS만으로 지하철 내부의 현재 역·칸을 정확히 안다고 가정하지 마세요.

6. 결과 제출
필수 파일: api-research-results.txt
선택: 비밀 제거 응답 조각, 공식 문서 PDF/텍스트 등 근거 파일.
클라우드 에이전트가 링크를 열지 못해도 판단하도록 핵심 정의·필드·조건을 본문에 요약하세요.
결과 구성:
1) 요약: 추천 API 조합, 가능한 기능, 부족한 기능, 추가 확인 사항.
2) URL별 로컬 접속 결과와 시각.
3) 비교표: 공급자/상품 | 역할 | 지원 범위 | 비용·제한 | 인증 | 근거 | 검증 수준.
4) 상세 안내 표: 요구 항목 | 공급자·필드 | 범위 | 근거 | 미확인 사항.
5) 혼잡도 표: 교통수단·지역 | 단위 | 실시간/예측/통계 | 갱신 | ID 연결 | 근거.
6) 실제 호출 기록 또는 미실행 이유·필요 권한.
7) 첫 버전 권고: 조합과 대안, 누락 시 처리, 추천 로직 한계.
8) 후속 작업: 계정·상품·키·접속 도메인과 공급자에게 확인할 질문.
9) 공식 URL·문서 제목·절·확인일·핵심 내용 목록.
각 결론에 ‘공식 문서 확인’, ‘실제 호출 확인’, ‘미확인’을 표시하세요.
최종 공급자 선정과 비용 지출은 제안으로 남기고, 미확인 기능·미실행 응답을 확정적으로 쓰지 마세요.
